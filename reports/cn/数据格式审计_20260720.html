三、中盘缺失根因（数据覆盖缺口，非解析 bug）

实测：采集快照相对开赛时间的"采集终点"分布——中位仅 13 分钟，72% 的比赛在开赛 30 分钟内就停止采集，只有 27% 延伸到中场（45+ 分钟）。

根因：采集器每轮从 GQ API 拉 fetch_match_list()（仅含 API 当前标记为 live/upcoming 的比赛）。一场比赛在开赛约 13 分钟后就从该列表掉出，采集器不再抓取其赔率 → 中场时段无数据。

佐证：minute_at 字段对所有快照恒为 0——采集器未记录比赛进行分钟，只能靠 captured_at 相对开赛时间定位中盘，而快照根本没延伸到中场。

四、已做的修复 + 待办

已落地（安全、零风险）： gq_odds_filter.get_ht_close 增加回退窗口——严格中场窗口(44~52min)取不到时，依次尝试 35~65 / 30~75min，优先真中场。中盘覆盖从 491→537(CS)、422→480(1X2)、42→229(AH) 小幅提升。此改动为纯读取逻辑，不影响写入。
待办（需改采集器，涉及运行中的守护进程，需你拍板再动）：
让采集器自建"进行中比赛观察表"——比赛一旦开赛即从 API 列表移入本地观察表，持续抓取赔率至终场（0~95min），不再依赖 API 是否仍把它列在 live 组。这是中盘覆盖率从 ~25% 提升到接近 100% 的唯一根本解法。
