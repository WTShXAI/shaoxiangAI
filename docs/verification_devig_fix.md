# 验证台去水口径事故 — 伪 EDGE 发现与修复 (2026-09-23)

> 级别: **P0 度量事故**。验证台唯一过线的盈利判定 (KNN = EDGE) 经审计为度量伪影,
> 非可交易预测能力。已在门禁层根治, 判定翻转为 NO EDGE。

## 1. 事故陈述

验证台 2026-09-22 建成并持续运行, 判定:

| model_source | n | ROI | 95%CI | 旧判定 |
|---|---|---|---|---|
| candles_ensemble | 181 | -0.07% | [-16.15%, +16.51%] | INCONCLUSIVE |
| market_baseline | 6081 | +3.49% | [+0.93%, +6.11%] | NO EDGE |
| **KNN** | 2562 | **+5.86%** | **[+1.62%, +10.10%]** | **EDGE** |

KNN 是唯一通过五道关的模型, 也是"公司能否盈利"的唯一希望寄托。

## 2. 根因: 比例法去水高估热门概率 (favorite-longshot bias)

`verification/ingest.py` 去水入口为 `pipeline.odds_math.devig3` — **比例法**:
抽水按各结果概率**比例**均摊 (p_i = (1/o_i) / Σ(1/o_j))。

真实市场的抽水分配并非比例均摊, 而是更偏向冷门 (FLB)。比例法因此**系统性高估
热门的真实概率** (即把热门的去水赔率抬得过高), 使"买热门"产生虚正 ROI。

讽刺的是项目 SSoT 自己知道这点 — `pipeline/odds_math.py::devig_power` 的 docstring
写明"比比例法更抑 FLB", 但验证台没用它。

### 证据链 (全部可复现, 脚本见文末)

**(a) ROI 随赔率单调递减** — 教科书级 FLB 特征:

| 赔率档 | n | ROI |
|---|---|---|
| <1.5 | 397 | +9.68% |
| 1.5–2 | 731 | +8.06% |
| 2–3 | 1018 | +4.74% |
| 3–5 | 413 | +1.83% |
| >5 | 3 | -100% |

回归 ROI ~ log(odds) 斜率 = **-0.1225, t = -89.5** (极端显著)。

**(b) 零信息机械策略显著盈利** — 决定性:

在 KNN 下注的**同一批 2562 场**上, 完全不用模型的机械规则:

| 策略 | n | ROI | 95%CI |
|---|---|---|---|
| KNN 实际 | 2562 | +5.86% | [+1.65%, +10.05%] |
| **无脑买最短赔率(热门)** | 2562 | **+5.15%** | [+1.20%, +9.09%] |
| 无脑买最长(冷门) | 2562 | -9.86% | [-17.58%, -1.65%] |
| 无脑买平局 | 2562 | -15.10% | [-21.55%, -8.61%] |
| 均匀随机选边 | 2562 | -3.85% | [-10.10%, +1.97%] |

**配对差 KNN − 无脑买热门 = +0.71pp, 95%CI [-3.59%, +4.97%] — 含 0。**
即 KNN 相对"什么都不做只买热门"没有任何可分辨的超额。

**(c) 零信息对照 market_baseline 6081 场 ROI +3.49% (CI下限 +0.86% > 0)**
— 去水后公平赔率上的零信息策略本应 ROI≈0, 实测显著为正, 直接度量了 devig 残差偏差。

**(d) 换幂法后 KNN 表观 ROI 塌落**:

| 口径 | KNN ROI | 机械买热门 ROI | 配对差 |
|---|---|---|---|
| 比例法 devig_n | +5.86% | +5.15% | +0.71pp (CI含0) |
| **幂法 devig_power** | **+2.37% (CI [-2.20%, +3.05%] 含0)** | +0.87% (CI含0) | +1.50pp (CI含0) |

比例法对热门赔率的虚高幅度: 平均 **+4.20%** (相对幂法)。
幂法口径复算自校验: 比例法重算值 vs 账本原值吻合率 **99.69%** (2552/2560) → 原始赔率口径正确, 复核可信。

## 3. 为什么旧五道关没拦住

| 关卡 | 判据 | 为何被"买热门"通过 |
|---|---|---|
| G1 样本 | n≥2500 | 2562 ✓ (纯数量) |
| G2 ROI CI | 下限>0 | +1.62% ✓ (就是 devig 偏差) |
| G3 质量 | vs_market_ll<0 **或** acc>1/3 | KNN 无概率 → 退化 acc>1/3; 买热门准确率天然>1/3 ✓ |
| G4 校准 | ECE/slope | KNN 无概率 → 全 None → "缺字段视为未违反" ✓ |
| G5 方向二项 | p<0.05 | 同样由热门倾向驱动 ✓ |

**五道关对无概率的方向型模型形同虚设。**

## 4. 修复

### 4.1 新增 G6 零信息机械对照关 (根治)

`verification/metrics.py` + `verification/gates.py`:

- 对每场计算"无脑买最短 devig 赔率"的纸盘收益, 与模型实际 payoff 做**同场配对差**
- 判据: 配对差 bootstrap 95%CI **下限 > 0**
- EDGE 需 G1–G6 全过; **G6 不过 → 直接 NO EDGE** (而非降级 INCONCLUSIVE)
- 缺失 devig 数据视为不通过 (无法证明超额即不得声称)

这是唯一能区分"真选边能力"与"吃热门偏差"的关卡。

### 4.2 去水口径改幂法

`verification/ingest.py`: `devig3` → `devig_power`。
账本新增 `devig_method` 列 (`power`|`proportional`, NULL=旧比例法行) 供跨口径追溯。

### 4.3 补回丢失模块

发现 `verification/` 包整体缺失 (仅剩 verification.db 8824 行账本), 报告产物亦丢失。
从 `backup/verification-platform` 分支恢复 9 个模块; 该备份本身缺 `_ir32.py`
(IR-32 守卫) 与 `__main__.py` (CLI 入口), 已按原设计重建。

## 6. 结论与含义

- 系统**不存在已验证的可交易统计边缘**。这与 2026-09-17 P0 诚实终判定
  (干净真相 GQ 2540 宇宙, 全部模型 FAILED) **一致** — 期间那个 EDGE 是度量伪影。
- 任何基于"KNN +5.86% ROI"的放量下注/资金配置决策都是把 devig 偏差当利润,
  实盘必亏。修复前若已按此决策, 属重大风险敞口。
- 账本 8824 行仍为比例法口径; 新行起用幂法。**跨口径样本不可直接混用判定**,
  待幂法样本独立累积至 2500 场后重判。

## 8. 教训

1. **正 ROI 不是 edge 的证据, 只是待解释的现象。** 任何盈利声称必须先过
   "零信息机械对照" — 不用模型的最笨规则能赚多少?
2. **去水方法的选择能凭空造出 4% 的 ROI。** 涉及赔率的度量, 口径必须显式声明
   并做多方法敏感性测试。
3. **无概率的方向型模型不能套用概率型门禁。** "缺字段视为未违反" 是危险的默认放行。
4. **备份分支也会不完整。** 恢复后必须实跑验证, 不能只看文件数量。
