## 一、结论先行（请先读这段）

本轮按用户指令"**换一个数据源，用滚球数据来回测**"。结果出乎此前假设，必须如实陈述：

1. **去水隐含(live)赔率是滚球 1X2 终场预测的最强单一预测器**（AUC≈0.80 / Acc≈0.64 / LogLoss≈0.82），印证博彩学定论——滚球盘口本身高度校准，直接跟盘即最优读数。
2. **本系统 live 概率层（动态泊松 λ + 等渗校准）并未超越、反而明显劣于去水隐含**：
   - ALL in-play：系统 AUC **0.7466** vs 去水隐含 **0.7967**（差 −0.050）
   - 比分已知子集：系统 AUC **0.7497** vs 去水隐含 **0.8202**（差 −0.070）
   - **LogLoss 灾难性恶化**：系统 5.88（比分已知 8.17）vs 去水隐含 0.82/0.74 → 系统概率严重失真/过置信。
3. **GitHub 冻结 HeuristicPredictor（仅赔率轨、无 live 特征）AUC 0.7964 ≈ 去水隐含 0.7967**，与基线持平。原因：它是赔率的直接函数（SP R1/R6 规则 + 去水），本质上≈去水隐含。
4. **此前"live 特征层拉开差距 / 系统 live AUC 0.885"的假设，在本测试口径下被证伪。** 该 0.885 数字需复核其评估任务/模型（见第六节）。

> ⚠️ 诚实边界：本结论针对"**单点 live 读盘 → 预测终场 1X2**"这一具体任务。系统在其他维度（OU 破蛋、半场动态、合理比分推荐）可能仍有独立价值，不能据此全盘否定系统。

## 三、方法论（确保可复现、无未来泄露）

- **数据源**：`events.db.odds_snapshots`（market='1X2'、minute_at>0、按 match_key+minute_at+score_at 聚合为完整 H/D/A 三元组，赔率取该分钟均值）关联 `match_outcomes.result`（home/draw/away）为真值。join key = `home || ' vs ' || away`。
- **OOS 定义**：events.db 的 in-play 采集集中在 **2026-07-30 ~ 2026-08-27 一个约 4 周窗口**，无更长历史跨度做"训练窗<测试窗"时间切分。故本次为 **held-out in-play 评估**：每个预测点只使用"该时刻可得信息"（当场 live 1X2 赔率 + 当前比分 + 当前分钟），无未来泄露；双方均为闭式/规则型，无 in-play 训练泄露。
- **本系统侧实现**（`analysis/live_goal_probe` + `analysis/inplay_calibration` 真实生产代码）：
  - `_dewater_1x2` 去水 → `_reverse_poisson_total` 反推静态 λ →（比分已知时）`dynamic_team_lambda` 以当前比分+剩余时间做贝叶斯收缩后验 λ(t) → `simulate_inplay_1x2` 终场 1X2 分布 → `isotonic_calibrate_1x2`（按联赛等渗校准，FLB 收缩）。即 `predict_fulltime_outcome` 内部 live 概率层。
- **GitHub 侧实现**（`agents/heuristic_predictor.py::HeuristicPredictor`，冻结仓唯一可无头入口）：纯 numpy 规则型 odds→probs（feature_weight=0.30 + odds_weight=0.70，SP R1/R6 规则）。**其 live 特征层（比分/分钟）在冻结态不可参赛**——HeuristicPredictor 不接受 score/minute，故任意 in-play 状态只用 live 赔率。
- **基线**：当场 live 1X2 去水隐含概率。
- 指标：sklearn `roc_auc_score(multi_class="ovr", average="macro")` / `log_loss` / 多类 Brier（Σ(onehot−p)² 均值）/ Top-1 Acc。

## 四、诊断：为什么系统 live 层会输给去水隐含

1. **滚球盘口已是最优校准预测器**。live 1X2 赔率随比分、剩余时间、动量实时调整，去水后即接近真实终场概率分布（市场效率，IR-17 同源结论）。
2. **本系统动态泊松层是"对已最优预测的近似重建"**。它从去水隐含反推 λ 再重模拟——无法超越已最优的输入，且引入近似/截断误差（Poisson maxg=8 截断、0-0 路径 `T_remain=2.5` 硬约束导致拟合 x2 偏差，表3 系统 0-0 仅 0.6745 < 基线 0.7039 即此因）。
3. **LogLoss 灾难（5.88 / 8.17）指向严重过置信/校准崩坏**。最可能诱因：**isotonic 校准器在 sklearn 1.9.0 下加载（训练于 1.6.1），版本错配**（`InconsistentVersionWarning` 已告警）。该步骤仅在 max(p)<0.9 时介入；但即便剥离开，核心 `simulate_inplay_1x2` 的 AUC 也已低于基线，说明退化不只在 isotonic。
4. **GitHub 持平基线属预期**：odds-based 启发式本质≈去水隐含，既未获 live 特征增益，也未引入额外误差。

## 五、与上一轮静态 OOS 的连贯叙事

| 测试 | 本系统 | GitHub | 去水隐含 | 结论 |
|---|---|---|---|---|
| 静态 OOS（收盘 1X2，n≈39k） | 0.670 | 0.671 | 0.671 | 三方平手（静态盘无可提取 edge） |
| **滚球 in-play（live 1X2，n=6000）** | **0.747** | **0.796** | **0.797** | **市场仍最强；系统 live 层未超越且退化** |

**统一结论**：无论在静态还是滚球 regime，**去水隐含市场概率都是跨系统的最强基线**；本系统的"附加层"（静态经验桶 / 动态泊松）均未证伪"市场最优"定论，滚球场景下甚至还劣化。这与上一轮"平手"结论一致且更尖锐——系统层的增量价值在此任务上为负。

## 六、对"系统 live AUC 0.885"主张的复核建议

记忆中"本系统实测 live_1x2 AUC 0.885"在本口径下不成立（本测试仅 0.747）。可能口径差异：

- **(A) 任务不同**：0.885 可能衡量的是"给定当前比分，领先方是否终胜"等二分类（trivially 高），而非三分类终场 1X2 概率质量。
- **(B) 模型不同**：0.885 可能来自 `data/live_1x2_model.joblib` 等独立训练 ML 模型，而非 `predict_fulltime_outcome` 的泊松路径（本次实测对象）。
- **(C) 子集/样本偏差**：可能取自特定联赛或已剔除困难样本。

**建议**：用同一 harness 改接 `live_1x2_model.joblib` 复测，或要求澄清 0.885 的评估口径，避免"自述数字"被当作采纳事实（遵循 v7.4 研究报告交叉核验的教训）。

## 七、已知未动 / 限制

- **GitHub 完整 live 流水线未参赛**：其四模型 LangGraph + Ollama + live 特征在冻结仓+无 LLM 下无法无头复现。本次 GitHub 仅以 heuristic 赔率轨参赛，故"GitHub≈基线"只说明其冻结入口≈去水隐含，不构成"GitHub 系统更优"的结论。
- **sklearn 版本错配**：系统 isotonic 在 1.9.0 加载（训练 1.6.1），可能额外拉低系统 LogLoss/AUC。需同版本（1.6.1）重跑确认。
- **数据偏斜**：in-play 窗口仅 ~4 周，且联赛分布偏 obscure/低级别（球会友谊赛、瓦尔哈拉杯、芬兰丁级、FIFA WC2026 等），非五大联赛代表样本。
- **单一任务**：仅终场 1X2 单点读盘，未覆盖 OU/破蛋/合理比分等系统有 narrative 优势的维度。
